## Findings by requirement

### 5. Comparisons — **PARTIAL**
The report shows a Solution comparison matrix (`_rd_md`; `Solution.name/pros/cons/scores`), but there
is **no first-class `Comparison`** capturing an atomic, evidence-linked data point (subject / criterion
/ value / unit / conditions / source / experiment / result / confidence per the master spec §16). No
model/schema/API/UI/KG type. Comparison values cannot be traced to evidence/results today. Reuse:
`Source`/`Experiment`/`Result` for links; the `Solution` table stays (qualitative recommendation
matrix) and coexists with a new atomic `Comparison`.

### 17. Limitations — **PARTIAL**
Limitations exist as **inline JSON note-lists** on `Method`/`Dataset` (and `Result.anomalies`), but
there is **no first-class `Limitation`** spanning the master-spec levels (source/dataset/method/
experiment/technology/research/statistical/environmental) with severity / affected-object /
evidence / impact / mitigation / status. No model/schema/API/UI/KG type. Reuse: keep the inline JSON
lists (quick notes) **and** add a cross-cutting `Limitation` object that references the affected
object + evidence; do **not** migrate/duplicate the JSON lists.

### 18. Research Gaps — **PARTIAL (extend, don't duplicate)**
`KnowledgeGap` is real and auto-generated, but minimal + read-only. Missing vs master spec:
`importance`, `impact`, `potential_investigation`, related-links (question/hypothesis/experiment/
claim/conclusion/evidence), `status` (structured), `confidence`, `provenance/origin`, and
create/update/delete API. **Extend `KnowledgeGap`** (additive nullable columns via `_ADDED_COLUMNS`)
+ add write endpoints; the auto-generated loop keeps working (new fields default). Do **not** create a
parallel gap system or duplicate monitoring/significance.

## Cross-cutting findings
- **Traceability:** the existing per-project **JSON id-list + `_validate_object_links`/`_LIST_REF_MODELS`**
  pattern (Phases B–D) is exactly what Comparison/Limitation/Gap links should reuse — no second
  relationship framework. Forward/reverse navigation is by the same id-lists the UI already drills.
- **Confidence/provenance:** reuse the 0–100 float (nullable, never fabricated) + `origin`
  (user/agent/derived). No second confidence engine.
- **Knowledge Graph:** `registry.py` has **no** `comparison`/`limitation`/`research_gap` entity types
  and **no** `compares`/`limits`/`affects`/`motivates` predicates. Add **vocabulary only**; builder
  node emission stays Phase G (unchanged behavior).
- **Report:** no structured Comparisons/Limitations sections; the "## Knowledge Gaps" section is **LLM
  prose** (gated by the Phase D narrative gate). Phase E should inject `## Limitations` and a structured
  Research-Gaps section **from rows** (the row is the source of truth), and render atomic Comparisons
  from `Comparison` rows — using the existing `_rd_md`/`_analysis_conclusions_md` deterministic-injection
  pattern, sections shown only when rows exist.
- **Research Again / Diff / Memory / Monitoring:** **defer** structured diff/memory/monitoring of
  comparisons/limitations/gaps (consumers, not blockers). Future flow *new evidence → new/resolved
  gaps, changed comparisons/limitations* reuses the existing `research_diff` + `significance` engines
  — no new diff/lineage engine. Document; do not build.
- **API/Capability:** `api/rnd.py` is the home; extend with CRUD reusing `_get_project` +
  `_validate_object_links`. `/v1` + MCP exposure **deferred** (matches Phases B–D).
- **Frontend:** no Comparisons/Limitations UI; gaps are read-only in `PlanTab`. Reuse the
  `AnalysisPanel`/`ExperimentsPanel`/`LabPanel` card+adder+classification-badge patterns for a new
  panel/tab; make gaps editable.
- **Security:** all Phase E objects use `_get_project` (cross-user → 404) + per-project reference
  validation (cross-project → 422), identical to Phases B–D. Required security tests mirror Phase D.
- **Database:** new `comparisons` + `limitations` tables (`create_all`); additive nullable columns on
  `knowledge_gaps` (`_ADDED_COLUMNS`). No existing table dropped; idempotent; Phase A–D data preserved.

## Truthfulness risks (documented, NOT fixed here)
1. A Comparison could assert a `value` with no supporting source/experiment/result → require ≥1
   evidence link (or explicitly mark it unsupported) at the API.
2. A Limitation could be invented → it must reference the affected object; `origin` records who
   recorded it; never auto-generated as "identified" without a source/analysis.
3. A Research Gap is an **absence of evidence**, not a claim — the report/UI must present gaps as open
   questions, never as verified facts; LLM-suggested gaps must be marked `origin="agent"` and never
   auto-`resolved`. The existing LLM "## Knowledge Gaps" prose must not become the source of truth —
   structured gap rows are authoritative.
4. No recommendation may cite a speculative gap as evidence (Phase D recommendation grounding already
   restricts links to conclusions/analysis/results — gaps are not a grounding type).

## PROPOSED MINIMAL ARCHITECTURE
**Two new tables + one extension** (not three new tables — Research Gap reuses `KnowledgeGap`):

1. **`Comparison`** (new; `models/analysis.py` or a small module): `subject_a` (required),
   `subject_b?`, `criterion`, `value`, `unit?`, `conditions?`, links `source_ids`/`experiment_ids`/
   `result_ids`, `confidence?`, `origin`, `notes`. Coexists with `Solution` (qualitative matrix).
   Truthfulness: require ≥1 of source/experiment/result **or** explicit unsupported flag.
2. **`Limitation`** (new): `ltype` (source|dataset|method|experiment|technology|research|statistical|
   environmental), `description`, `severity` (high|medium|low), `affected_kind`+`affected_id?` (or
   per-type id-lists), `evidence` link-lists `source_ids`/`claim_ids`, `impact?`, `mitigation?`,
   `status` (open|mitigated|accepted|resolved), `confidence?`, `origin`. Inline JSON lists on
   Method/Dataset remain (quick notes).
3. **Extend `KnowledgeGap`** (additive `_ADDED_COLUMNS`): `importance?`, `impact?`,
   `potential_investigation?`, `status` (open|investigating|addressed|wont_fix), `confidence?`,
   `origin`, link-lists `question_ids`/`hypothesis_ids`/`experiment_ids`/`claim_ids`/`conclusion_ids`/
   `source_ids`. Add write endpoints (`POST/PATCH/DELETE`) beside existing `GET`. Auto-generated gaps
   keep working (defaults).
- **Enums (string sets, migration-free):** `LIMITATION_TYPES`, `LIMITATION_SEVERITIES`,
  `LIMITATION_STATUSES`, `GAP_STATUSES` (+ patterns), in `models/enums.py`.
- **API:** `api/rnd.py` CRUD for `.../comparisons`, `.../limitations`, and gap write routes; ownership
  via `_get_project`; refs validated by extending `_LIST_REF_MODELS`.
- **Report:** deterministic `## Comparisons` (table), `## Limitations`, `## Research Gaps` from rows
  (only when rows exist); gaps shown as open questions, never verified facts.
- **KG:** add `comparison`/`limitation`/`research_gap` entity types + `compares`/`limits`/`affects`/
  `motivates` predicates (vocabulary only).
- **Frontend:** a new panel/tab (reuse `AnalysisPanel` patterns) for Comparisons + Limitations +
  editable Research Gaps; classification/severity/status badges; traceability drill-down.
- **Tests:** CRUD + validation + grounding + all type/severity/status values + cross-user 404 +
  cross-project 422 + offline (no LLM) + report row-injection + gap-not-a-fact truthfulness + migration
  idempotency (A–D preserved) + KnowledgeGap-extension backward-compat (auto-gen gaps still valid).
